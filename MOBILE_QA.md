# Перевірка Android та iPhone

## Ізоляція акаунтів — 2026-09-15

Поїздки, витрати, пальне, профіль, робочі зміни та резервні точки GPS тепер зберігаються окремо за Firebase UID. Гостьовий режим має власне сховище. Вихід не видаляє записи попереднього акаунта; повторний вхід відкриває його записи. Під час зміни акаунта закриваються попередні екрани, завершується активний GPS-запис для його власника, а запізнілі хмарні операції не змінюють дані нового акаунта.

Під час першого запуску оновлення старе спільне сховище прив'язується до акаунта, який уже увійшов у застосунок. **Перед встановленням оновлення потрібно увійти в основний акаунт у попередній версії.** Старий формат не містить власника кожної поїздки, тому автоматично розділити вже змішані записи неможливо. Якщо перший запуск відбувся без входу, старі записи залишаються збереженими окремо й не передаються наступному новому акаунту. Гостьові записи також не переносяться до акаунта автоматично.

На обох платформах додатково перевірити: створити поїздку в A, вийти, зареєструвати B (список порожній), створити поїздку в B, повернутися в A (видно лише поїздки A), перезапустити застосунок. Повторити вихід під час ручного й автоматичного GPS-запису та під час хмарного відновлення. Видалення B має залишити записи A.

Перевірки після виправлення: `flutter analyze --no-pub` — без зауважень; повний `flutter test --no-pub --concurrency=2` — **138 тестів пройшли** (`build/account_test.log`). Регресії перевіряють ізоляцію локальних даних, перемикання й повернення акаунтів, видалення, закриття старих маршрутів навігації, запізнілі GPS/хмарні результати, повторну спробу збереження GPS та відсутність дублювання пробігу.

Оновлений Android APK успішно зібрано: `build/app/outputs/flutter-apk/app-release.apk`, приблизно 61,8 MiB; журнал — `build/account_android_build.log`. iOS-збірка та перевірка на фізичних телефонах для цього виправлення не виконувалися.

## Результати

- `flutter analyze --no-pub`: без зауважень.
- `flutter test --no-pub --concurrency=2`: **101 тест пройшов**. Журнал: `build/mobile_test.log`.
- Widget-тести форм поїздки й пального: 320×568, шрифт 200%, відкрита клавіатура, оформлення iOS та Android — пройшли.
- `flutter build apk --release --no-pub`: успіх, `build/app/outputs/flutter-apk/app-release.apk`, приблизно 61,8 MiB. Журнал: `build/mobile_android_build.log`.
- Перевірка APK: `com.marvroute.app`, версія `1.0.0+5`, minSdk 24, targetSdk 36, бібліотеки `armeabi-v7a`, `arm64-v8a`, `x86_64` з правильними ELF-заголовками.
- Статична перевірка XML/Xcode-конфігурації та `git diff --check`: пройшли. iOS-збірка та фізичні телефони не перевірені.

Початковий запуск тестів і збірки натрапив на переповнений диск. Після звільнення місця користувачем нативні бібліотеки перегенеровано, збірку й перевірки виконано повторно; наведені вище результати стосуються повторного запуску.

## Виправлення

- iOS: CocoaPods у Debug/Profile/Release, мінімальна iOS 15, делегат сповіщень у відкритому застосунку.
- Android: врахування загального блокування сповіщень, резервний перехід у налаштування на пристроях без окремої системної сторінки.
- GPS: збереження пробігу та часу початку після обмеження кількості точок, захист від одночасного старту/зупинки, обробка завершення потоку, оригінальні часові мітки GPS та завершення запитів за таймаутом.
- Автоматичні поїздки: резервний запис видаляється після успішного збереження; повторне відновлення використовує той самий ID; завершення старої поїздки не очищає резервний запис нової.
- Відновлення моніторингу перевіряє наявні дозволи, увімкнену геолокацію та видимість застосунку. Оновлення налаштувань не завершує поточну поїздку.
- Перевірка стану сповіщень iOS не відкриває запит дозволу; фонові повідомлення поважають вимкнені сповіщення.
- Десяткові числа підтримують крапку, кому й арабський роздільник; некоректна ціна пального більше не перетворюється мовчки на нуль.
- На Android/iOS CSV та JSON зберігаються через системний вибір файлу з правильним розширенням; скасування не показується як успішний експорт резервної копії.
- Виправлено переповнення списків вибору та картки GPS на вузькому екрані з великим шрифтом; після обриву ручного GPS-потоку доступна кнопка збереження зібраних даних.
- Щоденна резервна копія перевіряється при поверненні в застосунок; її завершення зберігає актуальні налаштування, а розклад враховує календарні дні.
- У CI додані Android- та iOS-збірки. Метадані Firebase узгоджені з поточними локальними конфігураціями.

## Перевірка на пристроях

Виконати на фізичному iPhone з iOS 15+ та Android з API 24+, окремо на сучасному Android з дозволом на сповіщення. Бажано включити Samsung або інший пристрій з агресивними обмеженнями фонової роботи.

| Сценарій | Очікуваний результат |
| --- | --- |
| Чиста інсталяція, реєстрація, вхід, перезапуск | Застосунок відкривається, сесія відновлюється, гостьовий режим доступний |
| Геолокацію відхилено або вимкнено | Зрозумілий стан, перехід до налаштувань; запис не показується активним |
| Лише приблизна геолокація | Немає збою; перевірити фактичну точність маршруту |
| Ручна поїздка 20–30 хв, екран заблокований, інша програма відкрита | Пробіг і маршрут збережені, запис доступний після зупинки |
| Автовизначення, поїздка, стоянка понад 3 хв | Поїздка збережена для перегляду; моніторинг продовжується |
| Зникнення GPS/відкликання дозволу під час поїздки | Активний стан завершується; зібрані дані доступні для збереження |
| Перезапуск після завершення автоматичного запису ОС | Відновлення останньої резервної точки без дублювання |
| Сповіщення дозволені, відхилені, вимкнені в налаштуваннях | Правильний статус; тест не заявляє успіх при відмові |
| Введення 12,5 / 12.5 | Значення збережене як 12.5 |
| Малий екран, великий шрифт, клавіатура, поворот | Поля й кнопки доступні, немає переповнення |
| PDF, CSV, JSON-експорт та імпорт JSON | Файли відкриваються відповідними програмами, дані відновлюються |
| Хмарна копія й відновлення на другій платформі | Дані правильного акаунта відновлюються без втрати записів |

## Межі перевірки

Windows не може скомпілювати або запустити iOS-версію. Перевірка конфігурації та widget-тести не замінюють Xcode й фізичний iPhone. CI підготовлено локально; запуск у GitHub не виконувався. Фізичний Android не був підключений. GPS із заблокованим екраном, системні діалоги, експорт через інші програми, Firebase-вхід/правила й відновлення між телефонами потребують перевірки вище.

Ручний запис досі зберігає поточні точки в пам'яті: повне завершення процесу ОС до зупинки ручної поїздки може їх втратити. Автоматичний запис має резервну точку приблизно кожні 30 секунд; це не гарантує безперервну роботу після примусового завершення процесу. Щоденна хмарна копія виконується в доступному процесі та при поверненні в застосунок, а не гарантовано у фоні о 23:59.

Gradle 8.14 / AGP 8.11.1 / Kotlin 2.2.20 збираються з поточним Flutter, але SDK попереджає про майбутнє припинення їх підтримки. Велике оновлення цих інструментів не входило в перевірку.
